# Batch 004 benchmark eligibility research

As-of date: 2026-09-09. The active evidence window is 2026-07-11 through 2026-09-09. A page or leaderboard being reachable on the retrieval date does not establish that its model results were published or evaluated inside that window. Both profiles below therefore record the date gap explicitly.

## LiveBench

**Canonical profile.** LiveBench is an objective-answer LLM benchmark designed to reduce contamination through refreshed questions. The benchmark-author site currently describes 23 objective tasks across seven categories and shows release `LiveBench-2026-06-25` as the latest release. The release date is 2026-06-25, outside this batch's result window, and is a question-set release rather than a model-result event. Primary sources: [official LiveBench site](https://livebench.ai/), [LiveBench repository](https://github.com/livebench/livebench), [repository changelog](https://raw.githubusercontent.com/livebench/livebench/main/changelog.md), and the [LiveBench paper](https://arxiv.org/abs/2406.19314).

**Protocol.** The official project describes automatically verifiable objective ground truth and no LLM judge. The repository's evaluation command selects an explicit release with `--livebench-release-option`, and the current site identifies the 2026-06-25 release. The official site exposes overall and category scores, but the rendered leaderboard does not expose a per-row evaluation/publication date, a frozen result artifact date, or a protocol commit for the model rows. The repository history does show maintenance commits inside the window—for example, configuration and harness commits on 2026-07-16 through 2026-08-04—but these are not model-result events and must not be substituted for score dates: [commit history](https://github.com/livebench/livebench/commits/main).

**Model coverage.** The current official page visibly lists closed frontier configurations such as `Claude Fable 5 Max Effort` (83.0 overall), `GPT-5.6 Sol Max Effort` (81.0), `GPT-5.5 Thinking xHigh Effort` (80.2), and `Claude 5 Opus Thinking Max Effort` (80.1). The page offers an open-weights filter, but the accessible rendered table does not provide a dated, auditable result artifact for an open model alongside one of these rows. I found no benchmark-author artifact that establishes both a current frontier and a current open model result with event dates in the allowed window. Do not infer a result date from a model release date, the 2026-06-25 question release, a page retrieval date, or an unrelated repository commit.

**Eligibility proposal.** `unverified` for this batch. The benchmark itself is useful and its protocol is sufficiently described, but the current evidence lacks benchmark-author publication/evaluation dates for exact model scores. A future qualifying evidence record should cite a dated official result artifact or commit containing the score, exact model ID and configuration, release/version, and score unit; it should include one frontier and one open model from different organizations under the same LiveBench release and evaluation protocol. The 2026-06-25 release alone cannot satisfy the rolling-60-day result requirement.

## SWE-bench Pro

**Canonical profile and dataset split.** SWE-bench Pro is a long-horizon software-engineering agent benchmark. The benchmark-author Scale page distinguishes 1,865 total problems across 41 repositories: 731 public instances, 858 held-out instances, and 276 private instances from 18 proprietary startup repositories. Results on the public and private sets are separate; the held-out set is not published. Primary sources: [Scale public methodology and leaderboard](https://labs.scale.com/leaderboard/swe_bench_pro_public), [benchmark-author repository](https://github.com/scaleapi/SWE-bench_Pro-os), [public dataset](https://huggingface.co/datasets/ScaleAI/SWE-bench_Pro), and [benchmark paper](https://arxiv.org/abs/2509.16941).

**Protocol and version distinctions.** Scale defines Resolve Rate as the percentage of tasks whose patch passes both the new fail-to-pass tests and all existing pass-to-pass regression tests. The current public Scale leaderboard identifies the public dataset and reports 731 rows in the dataset card. The public leaderboard currently marks many rows with the mini-SWE-agent harness; its legend says starred models used mini-SWE-agent, while other rows use SWE-Agent, and it distinguishes capped 50-turn runs from uncapped 250-turn runs. The older benchmark-author static page reports an initial unified-scaffold table with an uncapped cost and 250-turn limit, but explicitly says those results are subject to change pending an official Scale announcement. These are materially different harness/turn-limit configurations and must not be merged. The benchmark repository also documents that its public, held-out, and private subsets differ in access and that the public leaderboard is separate from the private leaderboard.

**Current model results.** The current Scale public leaderboard PDF contains exact public-set rows including `gpt-5.4 (xHigh)` 59.1, `claude-opus-4-6 (thinking)` 51.9, `gemini-3.1-pro (thinking)` 46.1, `qwen3-coder-480b-a35b` 38.7, `gpt-oss-120b` 16.2, and `glm-4.6` 9.67. This supplies frontier and open-weight candidates from different organizations, and the PDF clearly labels the public dataset. However, the official PDF and HTML do not state the result publication/evaluation event date. The HTTP retrieval date is 2026-09-09, but that is not evidence of when the runs occurred; the static benchmark page itself says its initial table is pending official announcement. The benchmark-author repository history contains maintenance notices and harness changes, but no dated score artifact that binds these exact public rows to 2026-07-11 through 2026-09-09.

**Eligibility proposal.** `unverified` for this batch until Scale publishes or exposes a dated result artifact for the exact public rows. Once a dated artifact exists, a compatible pair could be proposed using, for example, `gpt-5.4 (xHigh)` and `qwen3-coder-480b-a35b` only if the artifact establishes their organizations, open-weight status, same public dataset version, same harness, same turn/cost limits, and the result event date. Do not combine the static 250-turn SWE-Agent table with the current public PDF's starred mini-SWE-agent rows, and do not use private-set results as public-set evidence. The benchmark-author sources support the protocol and split distinctions, but current date evidence is insufficient for the rolling-60-day gate.

## Sources and mechanical caveat

The source URLs above are benchmark-author or benchmark-maintainer primary sources, except the linked paper where it is the original benchmark publication. This document proposes eligibility evidence; it is not an approved evidence record and does not establish source truth mechanically. A qualifying record still needs independent review, exact result event dates, exact model/configuration identity, and compatible frontier/open coverage from different organizations.
