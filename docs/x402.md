# x402 prepaid credits (MODEL-75)

HTTP 402 with x402 v2 payment requirements; prepaid credits drawn down one
unit per successful result; per-call 402 for a caller with no balance.
Settlement is verified with Coinbase's CDP facilitator **before** any answer
is written. Independent of Stripe (MODEL-73). Ships behind `X402_ENABLED`,
default off.

## The switch: `X402_ENABLED`

A `vars` entry in `api/worker/wrangler.jsonc`, shipped `"false"`. Same reading
rule as `ACCESS_ENFORCED`: `"false"`, `"0"`, `"no"`, `"off"` and `""` (and
unset) are off; anything else is on.

Off: every request is answered as before. The Durable Object is not written.
On: `/v1/rank` and `/v1/policy-check` require either a prepaid credit or a
settled x402 payment for a delivered result. `/v1/health` is free.
`GET /v1/credits` reports the holder's balance and does not charge.

`X402_MAINNET` is a second flag, also off. On Sepolia (`eip155:84532`) until
someone sets that flag **and** the network, asset and `payTo` for Base
mainnet. The Worker will not remap Sepolia addresses onto mainnet by itself.

## Price, asset, payTo are configuration

| var | shipped | meaning |
|---|---|---|
| `X402_PRICE_ATOMIC` | `1000` | PLACEHOLDER. Atomic USDC, 6 decimals. `1000` = $0.001. Allowed range 1000–10000 ($0.001–$0.01). Not a live rate. |
| `X402_NETWORK` | `eip155:84532` | Base Sepolia CAIP-2 |
| `X402_ASSET` | Circle USDC on Base Sepolia | see sources |
| `X402_PAY_TO` | empty | receiving address; must be set before the flag is flipped. No private key. |
| `X402_FACILITATOR_URL` | `https://api.cdp.coinbase.com/platform` | origin; `/v2/x402/verify` and `/v2/x402/settle` are appended |

A price change is an edit to `wrangler.jsonc` (or `--var`), never to a module.
`X402_PAY_TO` empty while the flag is on is `500 x402_not_configured`, not a
guessed address.

## Turning it on

Facilitator auth is Wrangler **secrets**, not vars. The Worker mints a JWT for
each `verify` and each `settle` from `CDP_API_KEY_ID` and `CDP_API_KEY_SECRET`
(Ed25519 or ES256, whichever the portal issued). A static token cannot work.
CDP JWTs expire in two minutes and are scoped to one method + host + path
([JWT authentication](https://docs.cdp.coinbase.com/get-started/authentication/jwt-authentication),
read 2026-09-18).

```
npx wrangler secret put CDP_API_KEY_ID --config api/worker/wrangler.jsonc
npx wrangler secret put CDP_API_KEY_SECRET --config api/worker/wrangler.jsonc
```

Then set `X402_PAY_TO` to the receiving address and flip `X402_ENABLED`. Missing
secrets mean the facilitator is called without `Authorization` and the caller
sees `payment_failed`.

`CDP_JWT` is a local-testing override used only when those two secrets are
absent. It is refused when `X402_MAINNET` is on. Do not put a JWT in production
secrets. It will have expired before the next request.

The JWT `uri` claim is `{METHOD} {host}{path}`, for example
`POST api.cdp.coinbase.com/platform/v2/x402/verify`. The same value is also
sent as `uris` (an array). The JWT authentication page's language samples set
`uri`; the CDP SDK those pages recommend (`generateJwt`) sets `uris`. Extra
claims are ignored by a verifier that does not read them.

## What a 402 contains

Unfunded request, flag on:

- HTTP 402
- Header `PAYMENT-REQUIRED`: base64 of the x402 v2 `PaymentRequired` object
  (version, error string, resource, `accepts`)
- JSON body in the ModelSpec envelope: `error.code` `payment_required`,
  `error.price` (amount, asset, network, USD), `error.payTo`,
  `error.resource`, `error.accepts`, `error.how_to_pay`

Retry with `PAYMENT-SIGNATURE` (v2, base64 JSON) or `X-PAYMENT` (v1 alias).
The payload's `authorization.to` must be `X402_PAY_TO`; any other recipient
is `400 invalid_payment` and is never sent to the facilitator.

## Prepaid credits

Keyed to `key:` + SHA-256 of the presented API key (the live path only). A
settled payment of N × price credits N units. One unit is reserved before
`produce` runs and committed only when the result is HTTP 200 with a
non-empty `result`. A 4xx, 5xx, empty list or no-match **releases** the
reservation, so the balance does not move.

Drive-by (no API key): per-call 402. A settled payment is that request's
ticket. Leftover units are not stored under a payer address, because anyone
could present that address. Replay of the same payload is refused.

`GET /v1/credits` with the same API key returns `available`, `reserved`,
`total`. No key is `401 missing_holder`.

## Concurrency

Workers KV is eventually consistent and has no compare-and-set. It is **not**
the credit store.

Credits live in one Durable Object, class `CreditsObject`, binding `CREDITS`,
instance name `ledger`. The object is a serial mailbox: every `credit`,
`reserve`, `commit`, `release` and `seen` runs in order. That is the
guarantee:

- a payment id is credited at most once
- `available` cannot go below zero
- two in-flight requests cannot both commit the last unit

Residual: all paid mutations serialize through one object, so under
contention they queue. That is latency, not a correctness hole. A Worker
killed after `reserve` and before `commit`/`release` can freeze that one
unit as `reserved` until the object is inspected; bound: one unit per
in-flight request for that holder.

SQLite in the object holds two JSON record kinds, the ones disclosed in
`docs/legal/privacy.md`.

## Attack classes (§5)

| Class | Defence | Test |
|---|---|---|
| Free-riding | unfunded → 402; `produce` is not called | `test_attack_free_riding_unfunded_never_produces` |
| TOCTOU | reserve before produce; commit only on a billable 200 | `test_attack_toctou_reserve_before_produce` |
| Front-running | `authorization.to` must equal configured `payTo` before verify/settle | `test_attack_front_running_wrong_payto_never_settles` |
| Verification ordering | `verify` then `settle` then `produce`, recorded on a trace | `test_attack_verification_ordering_settle_before_produce` |

Per-call settlement cannot be un-settled if `produce` then returns 5xx. The
on-chain transfer has happened. Prepaid drawdown is the path that costs
nothing on failure; drive-by overpay is consumed. That is stated rather than
hidden.
