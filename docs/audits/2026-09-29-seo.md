# Technical SEO audit, 2026-09-29 (MODEL-218)

This audit covers production `https://modelspec.dev` at commit `e0f375fb`, built 2026-09-29 19:11 UTC. It was taken from outside, with no Search Console or Bing sign-in. Rerun the crawl with:

```bash
PYTHONPATH=$PWD .venv/bin/python scripts/seo_audit.py --origin https://modelspec.dev
```

It needs the project environment, because it reads the discovery list from `pipeline.live`.

The script starts at `/` and at every sitemap URL. It follows every same-origin link and asset. It checks status, robots directives, canonical, title, description, `<h1>` and JSON-LD on each page. It fetches every file an agent is told to read. It exits 1 on any error.

- **Sitemap.** It is complete for what production publishes. All 8 URLs answer 200, are indexable and self-canonical. No indexable, self-canonical page is missing from it. What it cannot list is pages that do not exist: see "Sitemap scope".

  - `/pricing/` links `/cdn-cgi/l/email-protection`, which answers 404 to a crawler. Cloudflare's Email Obfuscation rewrites the `mailto:` link into it (draft 2).

- **Served HTML.** `/decide/` and `/graph/` have no `<h1>` in the HTML the server sends. Both render client-side. Google renders JavaScript, but most agents and other crawlers see an empty `#root` (draft 6).

## Structured data

This PR adds `pipeline/structured_data.py`. `pipeline/live.build` calls it once, on the tree production serves, so `/decide/` is covered even though the live step replaces that page with the Vite build. It writes one `@graph` per page. `tests/test_holding.py` holds `live.PAGES` and the module's page list together.

| Page | Types |
| --- | --- |
| / | Organization, WebSite, Dataset, SoftwareApplication (CLI), WebAPI + SoftwareApplication (API), SoftwareApplication (MCP server) |
| /decide/ | BreadcrumbList, WebApplication |
| every other page | BreadcrumbList |

- **Dataset.** It describes the export and the decision snapshot. It lists a download only when that file is in the tree being published. `version` is `export_schema_version` and `dateModified` is `built_at`.
- **CLI.** The version and PyPI URL are read from `pyproject.toml`. The offer is $0, because the pricing page says the offline CLI costs nothing.
- **API.** No offer is listed, because it has a paid tier.
- **Organization.** It carries the `sameAs` profiles from `brand/social/profiles.json`. This replaces `social_profiles.add_same_as`, which used to put `sameAs` on the first JSON-LD object on the page, and that object was the Dataset.
- **Validation.**
  - validator.schema.org reports 0 errors and 0 warnings for the home graph, the `/decide/` graph and a breadcrumb page. The first run flagged `codeRepository` on SoftwareApplication, a property schema.org defines only on SoftwareSourceCode, so it now sits under `isBasedOn`. The pre-PR MCP entry had the same warning.
  - `scripts/seo_audit.check_json_ld` applies Google's rich-result requirements: Dataset `name` and a 50 to 5,000 character `description`; BreadcrumbList positions, names and item URLs; Article `headline`. `tests/test_structured_data.py` runs it over every generated object.
  - Google's Rich Results Test requires a sign-in, so it is on Jamie's list below.
- **No software rich-result card.** Google shows one only with an `aggregateRating` or `review`. ModelSpec does not invent either, so the audit reports that as a warning and never an error.
- **Article.** There is no blog to mark up yet. The blog's requirements are draft 8.

The thresholds are LCP 2.5 s or less and CLS 0.1 or less. TBT stands in for INP in the lab.

Production publishes no model page, so the third key page is `/method/`, the evidence page a model decision links to.

**Worst key page: `/decide/` on mobile.** This PR fixes two causes.

1. **CLS 0.177.** The only shifting element was `footer.site-footer`. The app painted the footer inside the first viewport, then the board loaded and pushed it down. `main.work` now has `min-height: 100vh`, so the footer starts below the fold.
2. **LCP 2.6 s, render delay 1.95 s.** The LCP element is the board's `<h1>`, which `FacetBoard` rendered only once the vocabulary fetch had finished. The intro is now `BoardIntro`, rendered by `App` before the vocabulary loads. The intro now sits in `main.work` instead of `.facet-board`. It looks the same, because both use a 14 px gap.

These were measured against a local production build (`vite build`, `vite preview` proxying `/api` to modelspec.dev and `/v1` to api.modelspec.dev), with Lighthouse mobile run three times at each step:

| Build | LCP | CLS |
| --- | --- | --- |

| footer fix | 2.5 / 2.4 / 2.4 s | 0 / 0 / 0 |

## Ticket drafts for the orchestrator

1. **Purge the `/downselect/` edge-cache ghost.** `modelspec.dev/downselect/` serves the retired v1 wizard as a cached 200 (`s-maxage=604800`, `age` about 5.5 days, `x-robots-tag: noindex`). No deploy contains it.
   - Purge it, and any other retired v1 URL still cached.
   - Find the rule that gives an HTML page a 7-day `s-maxage`, since `_headers` sets none.
   - MODEL-214's upcoming ticket owns the 301s for v1 URLs. Purge after those land, or the cached 200 keeps winning.
2. **Cloudflare Email Obfuscation creates a 404 link on /pricing/.** The `mailto:` link becomes `/cdn-cgi/l/email-protection`, and crawlers report it as broken. Either turn Email Obfuscation off for modelspec.dev (Scrape Shield, a dashboard toggle) or accept the finding. Low priority.
3. **`/graph/` mobile performance.** Lab TBT is 1.2 s and LCP 3.7 s, from three.js and the force layout on the main thread. Paint a static poster first and start the simulation on idle or on interaction.
4. **The long tail has no indexable pages.** Production publishes 8 pages. No model, benchmark or template has a URL a search engine can index, because the v1 `/m/` and `/b/` pages were retired at the flip. Decide what an indexable per-model and per-template page looks like on the decide stack: static HTML, one `<h1>`, a canonical, a sitemap entry and JSON-LD. This is probably MODEL-219's scope (SEO content).
5. **Template landing pages.** Of the 40 decide templates, 30 are in the "By use" grid, each ranked on an axis such as best available, balanced, budget or fastest. They are natural answers to "best model for coding" searches, but a template has no URL. One static page per template, linking into `/decide/` with the template applied, would make them indexable. This can fold into draft 4.
6. **Pre-render the decide intro and a no-JS summary.** `/decide/` sends an empty `#root`. Put the intro and a `<noscript>` summary (what the board does, and links to the CLI, API and method) into `web/decide.html`. The h1 then exists for crawlers and agents that do not run JavaScript, and LCP stops depending on the JS bundle.
7. **og:image on `/graph/` and the legal pages.** They have none, so shared links render without a card. `pipeline/social_cards.py` already renders per-page cards.
8. **Blog SEO, for the blog site-section ticket (the "ticket 2" of the MODEL-222 design, `pipeline/blog.py`).** MODEL-224 confirmed that the generator renders no HTML, so these belong to the site section.
   - Per post: `BlogPosting` JSON-LD with `headline` (110 characters or fewer; the generator already caps it), `author` (`@id` `https://modelspec.dev/#organization`), `datePublished` and `dateModified` from `post.yaml` `revisions[].published`, a 1200 px `image` (a social card, not the 680 px charts), and `mainEntityOfPage`.
   - A BreadcrumbList: ModelSpec, then Blog, then the post.
   - A self canonical, a meta description, `og:image`, and one server-rendered `<h1>`.
   - Published posts and `/blog/` added to `pipeline/live.PAGES` at build time from `blog/posts/*/post.yaml`, never hard-coded.
   - `scripts/seo_audit.check_json_ld` validates `BlogPosting`, so the blog's tests can call it.
