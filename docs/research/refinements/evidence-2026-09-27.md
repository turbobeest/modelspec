# Refinement taxonomy from the benchmark evidence

**Question.** Once a person picks a broad domain on the facet board, which finer criteria can ModelSpec honestly offer? This file derives candidates from what the benchmark catalogue and the model cards actually hold, and gives each one a verdict.

**Sources, read 2026-09-27.**
- Catalogue and cards: `origin/main` at `d1803b9b`, exported read-only.
- The live vocabulary: `https://modelspec.dev/api/decision/vocabulary.json` (snapshot `snap_f0a30b23be5070c7`, 39 benchmarks, 32 lineup models).
- A local snapshot built from `origin/main` with `decision.snapshot.build_from_repo(premier=premier/slice-1.yaml, gate=False)`. It has 41 benchmarks, the 39 plus `arena_elo_vision` (2 lineup models) and `simpleqa_verified` (17). Neither of the two carries a domain tag.
- LMArena `lmarena-ai/leaderboard-dataset`, read through the Hugging Face datasets-server `statistics` and `filter` APIs. This is the source that MODEL-160 already ingests. Latest split: text and webdev published 2026-09-25, vision 2026-09-13.

Per-benchmark data: `benchmarks.csv` (1,133 rows). Scripts: `build_csv.py`, `refine.py`, `arena_parse.py`, `gen_tables.py`.

### Where finer detail lives today

1. **As separate benchmark IDs, not as sub-scores.** The only sub-scores with lineup evidence are ID-per-slice:
   - 14 `arena_sc_*` categories plus the style-control overall;
   - `metr_time_horizon_50` and `metr_time_horizon_80`;
   - `mteb_v2_retrieval` and `mteb_v2_reranking`;
   - the `*_tools` variants.
   The 57 `mmlu_*` subject pages each carry evidence on 36–38 cards, all older models from the Open LLM Leaderboard. None is a lineup model.
2. **In page prose, not in structured fields.** The following exist only in `measures`, `size_note` or the body:
   - difficulty tiers (SWE-bench Verified easy/hard, KernelBench levels 1–4, FrontierMath tiers);
   - category lists (LegalBench's 6 reasoning types, HealthBench's 7 themes, WritingBench's 6 domains and 100 subdomains, Cybench's 6 CTF categories);
   - per-language item counts (Aider: C++ 26, Go 39, Java 47, JS 49, Python 34, Rust 30).
   `BenchmarkCard` has no field for task type, difficulty, industry, agentic mode or context length.
3. **In `dataset.languages`, which mixes programming and natural languages in inconsistent spellings**, for example `en` and `English`, or `java` and `Java`. After normalisation:
   - 41 pages name programming languages;
   - 245 pages name at least one non-English natural language: zh 107, es 39, de 34, ar 33, fr 33, hi/pt/ru 27, ja 20, ko 19, and 50+ others.
4. **The plumbing for sub-scores already exists and is unused.** `EvidenceValue.subcategory` exists in `decision/snapshot.py`, and `decision/optimise.py` accepts a benchmark selector with a subcategory, where omitting it means the aggregate. Per-language scores for SWE-bench Multilingual or MultiPL-E could therefore land as `subcategory` rows on the existing IDs, with no new benchmark pages.
5. **Some evidence sits on lineup cards but not in the snapshot.** These rows lack the v2 `id`, `sources` or verification, so the snapshot does not admit them:
   - `healthbench_professional` (3), `terminal_bench_science` (3);
   - `arc_agi_2` (2), `swe_bench_multimodal` (2), `hle_tools` (2);
   - `browsecomp` (1), `charxiv_reasoning` (1), `terminal_bench_v2_1` (1), `mmlu_pro` (1).
   Most of these pages are already domain-tagged. What is missing is verification, not tags.
6. **LMArena publishes far more slices than the catalogue ingests.**
   - `text_style_control`: 29 categories, of which 15 are ingested. Not ingested:
     - 9 languages: english, chinese, japanese, korean, russian, spanish, german, french, polish;
     - `hard_prompts_english`;
     - three industries: software/IT, entertainment/sports/media, mathematical;
     - `exclude_ties`.
   - `vision_style_control`: 11 categories, of which only `overall` is ingested. Not ingested: ocr, diagram, homework, humor, captioning, entity_recognition, creative_writing_vision, chinese, english, creative_writing.
   - `webdev`: html, react and image_to_webdev are not ingested.
   - Whole configs not ingested: `document`, `search`, `agent` (plus five `agent_*` diagnostic configs, not inspected row by row) and `text_factuality`.

   Lineup coverage in the latest split is 17–22 of 25 text generators for each language category. Two caveats on the Arena counts:
   - They count lineup models whose card-recorded Arena name appears in the latest split. That makes them a lower bound, because other effort variants are not matched.
   - For `agent` and `search` the names are display names, so they were matched by normalisation and are marked uncertain.

## How to read the tables

- **Isolates it**: the score itself is evidence for the refinement.
- **Partial / aggregate only**: the benchmark covers the slice but publishes only a mixed score on our cards. SWE-bench Multilingual covers Rust among nine languages, for example, but its score is not a Rust score.
- **Directness** is for the row's domain: `D` direct, `P` proxy, `u` untagged. For untagged pages the directness a tag *should* carry is my judgement and is not recorded anywhere.
- **Markers:** `*` means in the live vocabulary, `+` means in the `origin/main` snapshot only.
- **Brackets:**
  - `[sN]`: N lineup models in the snapshot;
  - `[cN]`: N lineup models with card evidence that the snapshot does not admit;
  - `[LN]`: N lineup models with only a quarantined legacy score.
- **Lineup models with evidence** is the union over the isolating benchmarks. Arena counts are for categories the catalogue does not yet ingest.
- **Verdicts:**
  - **LIVE NOW**: at least 2 lineup models have snapshot evidence on an isolating benchmark that is tagged to the domain. Cross-domain axes only need snapshot evidence.
  - **NEEDS TAGGING**: the evidence exists but is untagged for this domain, or is on cards but not in the snapshot, or sits in an already-used source (Arena) that is not ingested.
  - **NEEDS RESEARCH**: the catalogue has benchmarks, but no lineup-model scores. Legacy scores need re-sourcing.
  - **NO BENCHMARK**: nothing in the catalogue measures it.

## Cross-domain axes: notes

- **Natural language of the task** is the strongest cross-domain axis the data supports.
  - It exists as Arena preference in 9 languages, with 17–22 lineup models each. It is preference, so a tag would be `multilingual: proxy`.
  - Correctness-graded per-language evidence (Global-MMLU's 42 languages, MMMLU, MGSM, Belebele, language-specific suites such as CMMLU, KMMLU and ArabicMMLU) has no lineup scores.
- **Input length.** `arena_sc_longer_query` is about long prompts, not long context. The real long-context set has no snapshot evidence:
  - graphwalks, OpenAI MRCR, DeepMind MRCR v2, RULER, LongBench v2, XL-DocBench;
  - `graphwalks_bfs_256k_1m` has legacy scores on 2 lineup cards.
- **Modality.** Image is live through Arena vision. Document is in the Arena `document` config (14 lineup models, not ingested). Audio, speech and video have catalogue pages but no evidence on any card.
- **With vs without tools** is a clean paired axis (`hle` / `hle_tools`, `charxiv_reasoning` / `_tools`, `screenspot_pro` / `_tools`, `lab_bench_figqa` / `_tools`), but the `_tools` rows are not verified.
- **Difficulty** is live only as Arena "hard prompts" and "expert". Tiered sub-scores are described on pages but never recorded: SWE-bench Verified easy/hard, KernelBench levels, FrontierMath per tier.
- **Factuality** is a real gap in the domain list. `simpleqa_verified` is in the `origin/main` snapshot on 17 lineup models, but no domain can surface it because it has no tag. Arena `text_factuality` adds 22 more.
- **Reasoning effort** is a qualifier on evidence (`effort`: max, xhigh, high, medium), not a refinement of the task.

## The vocabulary's `task_types`

The 12 task types are the *outcome protocol's* types: `evidence.outcome`, parameterised by `outcome_task_types`. They are not a benchmark axis. Benchmarks map onto them only loosely:

| task_type | Benchmarks that map onto it | Lineup evidence |
|---|---|---|
| bug_fix | SWE-bench Verified, Pro, Multilingual, Multimodal, Java, Live; Multi-SWE-bench | Yes: 10 models in the snapshot |
| new_feature | DeepSWE v1.1 and FrontierCode 1.1 (partly; the pages do not split feature from fix), SWE-AGI, SWE-EVO, SWE-Lancer IC tasks | Yes: 16 (DeepSWE, FrontierCode) |
| refactor | SWE-bench ProMax | No |
| test_writing | None catalogued | — |
| docs | CodeXGLUE code-to-text only (weak) | No |
| migration | HumanEval-X code translation (weak) | No |
| performance | KernelBench, CodeInsights code efficiency | No |
| security_fix | None. CyberSecEval grades insecure-code generation, not fixes | — |
| review | None. FrontierCode grades whether the model's *own* change is mergeable, which is not reviewing others' code | — |
| analysis | DS-1000, CIBench, SciCode (data and scientific analysis) | No |

Only `bug_fix` and, loosely, `new_feature` have lineup-model benchmark evidence. The rest need outcome records, which is what the protocol exists for, or new catalogue entries. The absence of benchmarks for `test_writing`, `review` and `security_fix` is a catalogue gap, not a claim that no such benchmarks exist anywhere.

## Caveats

- Keywords in `benchmarks.csv` (`task_area_keywords`, `industry_profession`, `difficulty_markers`, `context_length_markers`, `agentic`) are regex heuristics over front-matter prose and tags. They are finders, not facts. The curated benchmark lists in the tables above were checked against page text.
- `programming_languages_in_prose` detects unambiguous language names in prose only. Go, R and C are detected only from `dataset.languages`.
- "Lineup models with card evidence" counts cards whose `benchmarks.evidence` names the benchmark ID, whether or not the snapshot admits the row.
- The live vocabulary lags `origin/main` by two benchmarks, and the catalogue's Arena rows (published 2026-09-13) lag the dataset's latest text split (2026-09-25): 18 versus 22 lineup models.
