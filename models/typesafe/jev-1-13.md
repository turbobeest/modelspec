# Jev 1.13

Jev is TypeSafe's System One model and the first `decision-model` in this
catalogue. TypeSafe's documentation describes System One as a class of models
built to make fast, structured decisions that software can use directly, and
says they do not write replies, produce code, or explain their reasoning
(`docs.typesafe.ai/concepts/system-one.md`, read 2026-09-20). You hand it
state, you hand it typed questions, and you get typed answers: a probability
(**Noul**, 0–1), a selected option with its full distribution and a confidence
(**Choice**, up to 255 options), or an ordered rubric of 2–10 levels resolved
to a probability-weighted value with a confidence (**Score**). Same source,
same date.

It is not an LLM, and the catalogue does not rank it as one. "Emits no tokens"
is the vendor's framing rather than a fact about the wire: the API reports
input and output token counts.

## Disclosure

**ModelSpec is a paying TypeSafe customer, and uses this model to judge
evidence for the catalogue.** `scripts/attribution.py` sends ambiguous creator
attributions — "who actually built the model this page lists?" — to Jev, and
pays per input token for the answer (MODEL-82).

So one rule binds this card and every future TypeSafe card: **no field on a
TypeSafe card may be written by a Jev judgment.** The refusal is in the code,
not in this paragraph. `supplier_conflict()` in `scripts/attribution.py` stops
the request before it is made when a supplier is among the candidates, and
`apply_policy()` refuses a stored judgment that names one, so neither a fresh
call nor a cached row can write here. `tests/test_attribution.py` fails if
either refusal is removed. Deterministic attribution still works — an id prefix
that reads `typesafe/…` is code reading a string, not the supplier's opinion of
itself — and anything ambiguous waits for a person.

Money flows to TypeSafe, not from it. Nothing here is paid placement, a
referral fee or provider-paid visibility, and the fact that we buy from a
vendor buys that vendor nothing in a ranking (see the neutrality commitment).
The disclosure is owed anyway, and it is derived from
`schema/suppliers.py` rather than typed into this file, so the next supplier
card cannot quietly omit it.

## Calling it, and what it costs

`POST https://api.typesafe.ai/v1/systemone`, Bearer auth, with a body of
`{state, model, questions}` (`docs.typesafe.ai/api`, read 2026-09-20). State is
text: a string, a JSON object or a JSON array.

**$0.042 per million input tokens. Output tokens are not charged**
(`docs.typesafe.ai/models.md`, read 2026-09-20). The documented limits, same
source and date: 250,000 tokens per **second**, 1,200 requests per minute,
64,000 tokens per request, of which state plus the longest single question may
be at most 32,000.

The model string is `jev-1.13.0`, with `jev-latest` and `jev-preview` as
aliases; Jev is the only published family member, and TypeSafe documents it as
trained with RLCD (`docs.typesafe.ai`, read 2026-09-20). The weights are
closed: the official Hugging Face organisation exists and publishes nothing
("None public yet", `huggingface.co/typesafe`, read 2026-09-20). Reproductions
by other groups are those groups' artifacts and are not carded as TypeSafe's.

## What this card cannot say

Four researched facts have no field in this schema. They are recorded here, and
in `cost.note`, rather than smuggled into a field that means something else
(MODEL-97, MODEL-98):

- **A price per decision.** `cost.input` is per million tokens. A caller of a
  decision model budgets per judgment — one request of state plus questions.
- **A per-second token limit.** `availability.primary_provider.rate_limit_tpm`
  is per minute. The published limit is 250,000 tokens per second, and
  multiplying it by 60 would publish a number nobody wrote down, so the field
  stays null.
- **The 32k state sub-limit.** `max_input_tokens` holds the 64,000-token
  request ceiling. The inner limit on state plus the longest question has
  nowhere to go.
- **RLCD as a training method.** `lineage.training_method` is an enum without
  it, so the card says `other` and names RLCD here.

Architecture is a different kind of blank. Parameters, layers and attention are
`null` because TypeSafe has not published them, not because the question is
meaningless — that is unknown, and the catalogue should keep asking. What the
class genuinely cannot answer — a maximum output-token count, a token stream,
an output tok/s — is derived from `model_type` and shown on the page as "not
applicable", never as a gap (`schema/applicability.py`).

## Evidence, and why it is unranked

TypeSafe publishes **zero benchmark numbers** for Jev. The catalogue therefore
carries none, and the ranker returns it `unranked` with
`insufficient_benchmark_evidence` and a null score. That is the correct
outcome: a model with no evidence is not a model that scored badly, and the
rank/unrank split exists precisely so absence is reported rather than priced
in. The standard suites do not rescue it either — MMLU, GPQA and SWE-bench
score generated answers, and this model generates none.

What TypeSafe does publish about failure is a jaggedness page for this version
(`docs.typesafe.ai/model-jaggedness/jev-1.13.md`, read 2026-09-20): nine
failure modes across arithmetic, dates, indirection, adversarial content in the
supplied state, and requests to generate rather than judge. No metrics
accompany them, so `known_failure_modes` carries the areas and nothing is
scored. Independent evaluations of Jev exist; only their existence was
verified, not their results, so none is cited.

## Adoption, tested rather than repeated

One usage figure is verified, and it belongs to one platform: **Vercel's own
blog (2026-09-18) reports the fastest adoption in its AI Gateway's history —
roughly 13% of paid AI Gateway teams within 24 hours.** That is a single
platform self-reporting about its own customers, which is evidence of real and
unusually fast uptake on that gateway and is not a market share. No second
independent usage source was found: `typesafe-sdk` exists on PyPI, but download
counts, repository stars and named customers are not established.

TypeSafe's homepage advertises large speed and cost multiples against
unnamed comparators. No methodology and no independent measurement accompany
them, so this card records no latency, throughput or cost-ratio figure, and
`inference_performance` is null throughout.
